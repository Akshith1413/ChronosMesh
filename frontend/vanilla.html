What ChronosMesh Does

Every Angle of Distributed Causality

From raw disordered events to a full causal graph with anomaly detection, root-cause tracing, and what-if analysis.

🕐

Pluggable Clock Systems

Lamport, Vector, and Hybrid Logical Clocks — all behind a swappable strategy interface for benchmarking and comparison.

🔗

Causal DAG Reconstruction

Computes happens-before relations, detects concurrency, builds a transitive-reduced DAG from any stream of out-of-order events.

⚡

Anomaly Detection

Flags time inversions, impossible causal cycles, duplicate events, and clock drift as first-class alerts — not just log noise.

🔭

Root-Cause Tracing

Backward DAG traversal from any failure event to its root causes. Find the origin in a distributed system with one click.

🎯

What-If Blast Radius

"If event X had NOT happened, what breaks?" Forward reachability analysis to compute the cascade depth and affected services.

📊

Confidence-Scored Edges

TrueTime-style probabilistic ordering using clock uncertainty intervals — statistical rigor beyond binary happens-before.

📖 ChronosMesh — GURU Layer

This document covers the API layer and frontend dashboard built by Guru Sai Prasad Reddy as part of the ChronosMesh Cloud Computing project.

The Guru layer sits between Akshith's core algorithm engine and the end user, exposing all reconstruction, analysis, and benchmarking capabilities through a clean REST API and an interactive web dashboard.

Design Principles

  • Clean API contract so Surya's Neo4j/Kafka layer can be swapped in without touching frontend code
  • JWT authentication with role-based access (admin / viewer)
  • In-memory store for demo mode — production-ready interface for future DB integration
  • All visualisations driven by live API calls — no static mock data in production mode

🔐 Authentication

ChronosMesh uses JWT (JSON Web Tokens) with bcrypt password hashing.

# Login — returns access_token curl -X POST http://localhost:8000/auth/login \ -d "username=guru&password=chronosmesh" # Use token in subsequent requests curl http://localhost:8000/api/dag/ \ -H "Authorization: Bearer <token>"

Tokens expire after 24 hours. The demo supports two users:

  • guru / chronosmesh — admin role (full access)
  • demo / demo123 — viewer role (read-only)

🕐 Clock Systems

Three clock strategies are implemented in Akshith's engine and exposed through the benchmark API:

1. Lamport Clocks

Scalar counter establishing a total order: a → b ⟹ L(a) < L(b). Cannot detect concurrency.

2. Vector Clocks

Per-node counter vectors: a → b ⟺ V(a) < V(b) (element-wise ≤, at least one <). Can detect a ∥ b.

3. Hybrid Logical Clocks (HLC)

Combines physical time with logical counter. O(1) space vs O(N) for vector clocks. Bounded drift detection.

🔗 Causal DAG Construction

The reconstructed DAG is a directed acyclic graph where:

  • Each node represents a distributed system event
  • Edge A → B means A causally precedes B (happens-before)
  • Concurrent events (∥) have no edge between them
  • The DAG undergoes transitive reduction to show only minimal edges
# Example DAG JSON response { "nodes": [{ "id": "abc123", "event_type": "ORDER_CREATED", "service_id": "order-svc", "lamport_ts": 1, ... }], "edges": [{ "source": "abc123", "target": "def456", "explicit": true }], "topological_order": ["abc123", "def456", ...], "roots": ["abc123"] }
